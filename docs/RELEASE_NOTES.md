Global Protector WiFi v1.1.7

- 内置越南网页和 SSH 中转，可在已连接的远程桌面会话中通过本机助手打开。
- 支持拖入文件上传到远程桌面 Inbox，显示远端已收到的字节数。已确认保存的文件会从队列移除。
- 支持暂停、继续上传、断点续传和断线自动重连。需要远端中转 v5。Windows 弹出登录提示时，登录后可继续上传。
- 修复分流日志共享、VPN 断线恢复和其他网络适配器切换时的异常。

从 v1.0.1 升级时，停止并退出旧助手，再运行本页的新版 EXE。首次打开越南网页请从新版助手启动远程桌面。已安装远端中转 v5 的会话可继续使用。

### v1.0.6 修复记录

- 停止、退出或分流发生致命错误时，使用官方 GlobalProtect 客户端请求断开，并等待实际断开后再清理原路由和 DNS。
- 官方客户端要求手动操作时保留分流，显示「请手动断开 VPN」。连接断开后自动继续恢复。
- GlobalProtect 自行掉线时清理本次分流并等待重连。助手工作进程意外退出时，界面启动一次独立恢复。

以下为 v1.0.5 本地修复记录：

- 路由与公网 IP 检查成功时，启动器在「DNS 待恢复」状态继续工作。DNS 恢复后回到「已连接」。
- 记录启动时的实际出口与公网连通性结果。默认远程桌面目标在验证失败时记录一次 TCP 3389 探测结果，探测不登录远程桌面。
- 网卡出口错误或公网 IP 持续不可达时执行恢复。

以下为 v1.0.4 本地修复记录：

- 其他网卡变化导致 GlobalProtect 加回原默认路由时，短暂观察并核实会话和原网络出口，再重新应用分流。
- 路由修复仅处理本会话记录的那条 GlobalProtect 默认路由，随后重新检查网络。其他网卡的路由、目标主机路由和 DNS 保持原配置。
- 遇到新会话、网关改变、目标路由丢失或同一路由被频繁加回时，停止自动修复并执行原有恢复流程。
- 离线复现并覆盖路由短暂出现、同一路由稳定重现、频繁加回、网关变化和会话变化。

以下为 v1.0.3 本地修复记录：

- VPN 已连接时，可在确认当前物理网卡和默认网关后直接启动分流，无须重新登录。
- DNS 失败时用第二个公网域名重试。自动模式还可在验证出口和解析结果后，临时使用原网络已配置的 DNS。
- 已成功应用分流的会话若仅 DNS 失败，保留当前分流并继续检查。真正的路由异常或持续公网 IP 失联仍触发恢复。
- 将连接 GlobalProtect 和配置分流分别显示，分流配置失败会保留其提示。

以下为 v1.0.2 本地修复记录：

- 修复 Windows PowerShell 5.1 中持续读取日志导致 Add-Content 写入失败、助手退出并触发网络恢复的问题。
- 日志使用明确的共享追加方式写入；文件被独占或不可写时，控制台仍向界面传递原始事件及非致命提示。
- 日志文件和控制台输出异常均不会触发网络恢复，界面的日志提示也不会标记分流失败。
- 分流、登录、凭据保存、恢复规则保持原样；不自动重启 VPN 或覆盖当前运行的助手。

使用 Windows PowerShell 5.1 验证持续读取、独占锁定、不可写路径、输出流关闭及锁释放后继续写入，并运行现有回归检查。
